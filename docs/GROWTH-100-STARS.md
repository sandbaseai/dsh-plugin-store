# 100 Star launch plan

## Goal

Reach 100 qualified GitHub Stars from DeepSeek Harness users, plugin authors, and Agent infrastructure developers.

The objective is not raw traffic. A qualified Star comes from someone who understands the product and may install, contribute, or share it.

## Baseline (2026-08-19)

| Metric | Value |
| --- | ---: |
| Stars | 0 |
| Unique repository visitors | 1 |
| Repository views | 3 |
| Unique clones | 23 |
| Total clones | 40 |

Clone traffic is likely influenced by automated discovery. Treat Stars, unique visitors, author replies, and confirmed installs as the primary signals.

## 14 day execution

### Days 1-2: conversion foundation

- Publish the new README and repository metadata
- Add a real screenshot or short GIF of Community and Installed views
- Open three starter issues: feedback, plugin submission, enterprise catalog requirements
- Cross-link from `awesome-dsh-plugin`, `deepseek-harness-handbook`, and `sandbase-harness`

### Days 3-4: warm launch

- Send the repository to 10 existing collaborators
- Contact the first 15 plugin authors with personalized notes
- Publish the Chinese community post
- Record objections and unclear installation steps

### Day 5: public launch

- Publish X / Twitter and LinkedIn posts within the same two-hour window
- Post the demo in relevant Discord, Slack, and WeChat groups
- Reply to every technical question within four hours

### Days 6-7: proof

- Publish a short demo showing tag filter, install, and Installed state
- Turn the top three questions into README FAQ entries
- Share the first contributor or plugin-author quote only with permission

### Days 8-10: technical communities

- Submit Show HN when installation instructions are reproducible
- Post to the most relevant Agent and DeepSeek subreddits
- Contact the next 15 plugin authors

### Days 11-14: second wave

- Publish what changed after early feedback
- Share a ranked list of useful plugins with the Store as the discovery path
- Ask existing stargazers for one relevant introduction, not another Star
- Review channel conversion and repeat only the top two sources

## Outreach rule

Do not send bulk generic messages. Each plugin-author note should mention the specific plugin, explain why it fits a category, and ask for one concrete action: validate its listing, test installation, or suggest missing metadata.

## Stop conditions

- Do not submit to Hacker News before the public install path is reproducible.
- Do not claim stable npm support until public DSH package versions match the integration APIs.
- Do not buy Stars or use engagement exchanges.
- Do not publish private customer names or unapproved quotes.
